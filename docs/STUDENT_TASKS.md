## 공통 시작 방법

```bash
npm install
npm run dev
```

수정 후 `npm run typecheck`와 `npm run build`를 실행합니다.

- 공통 타입: `src/tasks/taskTypes.ts` — 교사 관리, 학생 수정 금지
- 호환 진입점: `src/studentTasks.ts` — 교사 관리, 학생 수정 금지
- 개인 작업: 자신에게 배정된 `src/tasks/taskXX...`만 우선 수정
- 활동 기록: `docs/ACTIVITY_LOG_TEMPLATE.md`를 복사해 PR에 첨부

## Git 작업 규칙

1. 자신의 Issue 번호를 확인합니다.
2. `feature/student-번호-기능` 형식의 개인 브랜치를 만듭니다.

## 학생 1 — 가상 학번 검사와 학생 찾기

- **난이도:** ★☆☆ 입문
- **개발 목표:** 입력값을 정리하고 `F-1001` 형식인지 검사한 뒤 가상 학생을 찾는다.
- **담당 파일:** `src/tasks/task01StudentLookup.ts`
- **구현 함수:** `isDemoStudentId`, `findDemoStudent`
- **사전 학습:** `trim`, `toUpperCase`, 정규식 기초, `Array.find`
- **AI 활용 힌트:** “정답 전체가 아니라 `F-숫자 4자리` 정규식의 각 기호 의미를 설명해줘.”
- **테스트 방법:** `F-1001`, 공백 포함, 소문자, `1001`, 빈 문자열을 확인한다.
- **완료 기준:** 올바른 가상 학번만 참이고 존재하는 학생만 반환하며 원본 배열을 바꾸지 않는다.

## 학생 2 — 코인 지급과 동일 사유 중복 방지

- **난이도:** ★★☆ 기초
- **개발 목표:** 두 지급 사유마다 1코인을 지급하고 같은 사유의 재지급을 막는다.
- **담당 파일:** `src/tasks/task02CoinGrant.ts`
- **구현 함수:** `canGrantCoin`, `addCoinGrant`
- **사전 학습:** `some`, 배열 펼치기, 조건문, 불변성
- **AI 활용 힌트:** “`some`으로 학생 ID와 사유가 모두 같은 항목을 찾는 조건만 힌트로 줘.”
- **테스트 방법:** 첫 지급, 같은 사유 재지급, 다른 사유 지급을 확인한다.
- **완료 기준:** 중복 시 배열이 늘지 않고 새 지급은 1코인이며 기존 배열을 직접 수정하지 않는다.

## 학생 3 — 학생별 코인 잔액과 지급 현황 계산

- **난이도:** ★★☆ 기초
- **개발 목표:** 지급 합계에서 사용한 교환권 비용을 빼고 지급 사유 개수를 계산한다.
- **담당 파일:** `src/tasks/task03CoinSummary.ts`
- **구현 함수:** `calculateCoinBalance`, `countGrantedReasons`

- **AI 활용 힌트:** “`filter`와 `reduce`를 두 단계로 나누어 생각하는 방법을 예시로 설명해줘.”
- **테스트 방법:** 지급 없음, 지급 2건, 교환권 발급, 취소 교환권을 확인한다.
- **완료 기준:** 다른 학생 데이터가 섞이지 않고 취소 교환권 비용은 차감하지 않는다.

## 학생 4 — 간식 메뉴 조회와 구매 가능 여부

- **난이도:** ★☆☆ 입문
- **개발 목표:** 판매 중인 가상 간식을 찾고 현재 코인으로 교환 가능한지 판단한다.
- **담당 파일:** `src/tasks/task04SnackMenu.ts`
- **구현 함수:** `findEnabledMenu`, `canAffordMenu`
- **사전 학습:** 객체 속성, `find`, 비교 연산자, `undefined`
- **AI 활용 힌트:** “`>`와 `>=` 중 이 과제에 맞는 연산자를 테스트 사례로 설명해줘.”
- **테스트 방법:** 판매 중/중지 메뉴, 정확히 같은 잔액, 1코인 부족을 확인한다.
- **완료 기준:** 비활성 메뉴를 반환하지 않고 잔액이 비용 이상일 때만 참이다.

## 학생 5 — 모바일 교환권 발급 결과 만들기

- **난이도:** ★★★ 도전
- **개발 목표:** 잔액과 메뉴 상태를 확인하고 `issued` 교환권 또는 실패 메시지를 반환한다.
- **담당 파일:** `src/tasks/task05VoucherIssue.ts`
- **구현 함수:** `issueVoucher`
- **사전 학습:** 반환 타입, 객체·배열 복사, 고유 ID, 조기 반환
- **AI 활용 힌트:** “성공과 실패를 `{ ok, message, vouchers }`로 표현하는 이유를 설명해줘.”
- **테스트 방법:** 정상 발급, 잔액 부족, 판매 중지 메뉴, 기존 교환권 보존을 확인한다.
- **완료 기준:** 성공 시 한 건만 추가되고 비용·학생·메뉴·상태가 정확하며 실패 시 원본 내용이 유지된다.

## 학생 6 — QR 입력을 가정한 교환권 사용 처리

- **난이도:** ★★★ 도전
- **개발 목표:** 교환권 ID로 `issued`만 `used`로 바꾸고 중복 사용과 취소 상태를 거절한다.
- **담당 파일:** `src/tasks/task06VoucherUse.ts`
- **구현 함수:** `markVoucherUsed`
- **사전 학습:** `map`, 상태 전이, 실패 메시지, 불변성
- **AI 활용 힌트:** “issued→used만 허용하는 상태 전이 표를 먼저 만들어줘. 코드는 쓰지 마.”
- **테스트 방법:** 정상 사용, 같은 ID 재사용, 취소 교환권, 없는 ID를 확인한다.
- **완료 기준:** 허용된 상태만 변경되고 이유를 알 수 있는 메시지를 반환한다.
- **보안 구분:** 브라우저 시뮬레이션일 뿐이며 실제 중복 방지는 서버 DB의 원자적 검증이 필요하다.

## 학생 7 — 게임별 자동 랭킹 계산

- **난이도:** ★★★ 도전
- **개발 목표:** 종목을 분리하고 점수형은 높은 순, 시간형은 낮은 순으로 TOP 5/10을 만든다.
- **담당 파일:** `src/tasks/task07GameRanking.ts`
- **구현 함수:** `rankGameScores`
- **사전 학습:** `filter`, `sort`, `slice`, 숫자 비교 함수
- **AI 활용 힌트:** “higher와 lower 정렬식을 작은 숫자 세 개로 비교해 설명해줘.”
- **테스트 방법:** 점수형, 시간형, 다른 종목 혼합, TOP 5 제한, 원본 순서 보존을 확인한다.
- **완료 기준:** 선택 종목만 올바른 방향으로 정렬하고 제한 개수만 반환한다. 동점 정책은 문서로 제안하되 임의 확정하지 않는다.

## 학생 8 — 학생용 읽기 전용 교환권 카드

- **난이도:** ★★☆ 기초
- **개발 목표:** 교환권 상태를 쉬운 한국어와 색상으로 보여 주는 읽기 전용 컴포넌트를 만든다.
- **담당 파일:** `src/tasks/task08StudentVoucherCard.tsx`
- **구현 컴포넌트:** `StudentVoucherCard`
- **사전 학습:** React props, 조건부 렌더링, CSS class, 접근성 문구
- **AI 활용 힌트:** “발급됨·사용 완료·취소를 버튼 없이 구분하는 UI 아이디어를 세 가지 제안해줘.”
- **테스트 방법:** 세 상태를 각각 표시하고 모바일 폭에서 글자가 잘리지 않는지 확인한다.
- **완료 기준:** 상태가 한국어로 보이고 조작 버튼이 없으며 화면 읽기 도구에도 의미가 전달된다.
