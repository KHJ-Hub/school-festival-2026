# 2026 학교 축제 웹앱: 학생 8인 공동 개발 과제

이 프로젝트의 가장 중요한 목표는 8명 전원이 실제 코드를 읽고, 수정하고, 검증하는 것입니다. 각자 전용 파일 하나를 책임집니다.

> 개발과 테스트에는 `90001`처럼 **9로 시작하는 5자리 가상 학번**과 별명만 사용합니다(실제 학번은 1~3으로 시작합니다). 실제 학번·이름 등 개인정보는 코드·테스트·화면 캡처·Issue·PR에 절대 기록하지 않습니다.

## 서비스 흐름 (계획안 기준)

1. 학생이 부스에서 실물 코인을 모은 뒤, 자기 **학번(5자리)**과 **가진 코인 수**를 입력해 적립을 **신청**합니다. (학생 1·2)
2. 운영진이 실물 코인을 직접 확인하고 **승인**(수량 조정 가능) 또는 **거절**합니다. 승인된 만큼 학번에 코인이 적립됩니다. (학생 2)
3. 코인 잔액으로 팝콘 **교환권**을 발급받습니다. 맛보기컵 1코인 / 정식 1봉지 3코인 등. (학생 3·4·5·8)
4. 팝콘 라운지에서 교환권을 스캔해 **한 번만 사용 처리**합니다. (학생 6)
5. **누적 적립 코인** 순위를 실시간 랭킹으로 보여 줍니다. 교환권을 써도 순위는 내려가지 않습니다. (학생 7)

## 공통 시작 방법

```bash
npm install
npm run dev
```

수정 후 `npm test`, `npm run typecheck`, `npm run build`를 실행합니다.

### 내 코드가 맞는지 확인하는 방법

1. **테스트**: `npm test`로 전체를 돌리거나, 내 파일만 `npx vitest run task03`처럼 번호로 실행합니다. 처음에는 빨간색(실패)이 정상입니다. 초록색이 되도록 TODO를 구현하세요.
2. **화면**: `npm run dev` 후 **운영진용** 화면 아래의 "내가 만든 함수의 결과 보기"에서 결과를 눈으로 확인합니다.
3. 테스트 파일은 `src/tasks/__tests__/`에 있습니다. 테스트를 통과시키려고 테스트를 고치지 말고, 이해되지 않으면 Issue에 질문하세요.

### AI 활용 방식

이 프로젝트에서는 학생이 요구사항을 설명하고 AI(BeAT)가 코드를 쓰는 방식을 허용합니다. 다만 다음 세 가지는 학생의 몫입니다.

1. **설명하기**: 내 파일, 내 테스트, `taskTypes.ts`를 AI에게 함께 주고 무엇을 만들지 정확히 설명합니다.
2. **확인하기**: 테스트가 초록색인지 직접 실행해 확인합니다. 테스트를 고쳐서 통과시키지 않습니다.
3. **이해하기**: 내가 쓴 함수를 친구에게 내 말로 설명할 수 있어야 합니다.

아래 과제별 "AI 활용 힌트"는 "AI에게 정답을 받기 전에 먼저 이해해 볼 질문"으로 쓰세요. 자세한 순서는 `docs/DAY1_GUIDE.md`와 `docs/ONE_PAGE_CARD.md`에 있습니다.

### 파일 수정 범위

- 공통 타입: `src/tasks/taskTypes.ts` — 교사 관리, 학생 수정 금지
- 공용 가상 데이터: `src/tasks/fixtures.ts` — 교사 관리, 학생 수정 금지
- 테스트·결과 화면: `src/tasks/__tests__/`, `src/components/TaskPlayground.*` — 교사 관리, 학생 수정 금지
- 호환 진입점: `src/studentTasks.ts` — 교사 관리, 학생 수정 금지
- 공용 스타일: `src/styles.css` — 학생 수정 금지(충돌 방지). 학생 8은 `src/tasks/task08StudentVoucherCard.css`를 사용합니다.
- 개인 작업: 자신에게 배정된 `src/tasks/taskXX...`만 우선 수정
- 활동 기록: `docs/ACTIVITY_LOG_TEMPLATE.md`를 복사해 PR에 첨부

## 학생 1 — 학번 검사와 학생 찾기

- **난이도:** ★☆☆ 입문
- **개발 목표:** 입력값을 정리하고 숫자 5자리 학번인지 검사한 뒤 학생을 찾는다.
- **담당 파일:** `src/tasks/task01StudentLookup.ts`
- **구현 함수:** `isDemoStudentId`, `findDemoStudent`
- **사전 학습:** `trim`, 정규식 기초(`\d`, `^`, `$`), `Array.find`
- **AI 활용 힌트:** “정답 전체가 아니라 `숫자 5자리` 정규식의 각 기호 의미를 설명해줘.”
- **테스트 방법:** `90001`, 앞뒤 공백, 4자리·6자리, 문자 포함, 빈 문자열을 확인한다.
- **완료 기준:** 숫자 5자리만 참이고 존재하는 학생만 반환하며 원본 배열을 바꾸지 않는다.
- **개인정보 주의:** 테스트에는 `9`로 시작하는 가상 학번만 쓴다.

## 학생 2 — 코인 적립 신청과 운영진 승인

- **난이도:** ★★★ 도전
- **개발 목표:** 학생이 가진 코인 수를 신청하고, 운영진이 승인·거절하면 승인된 수량만큼 지급 내역을 만든다.
- **담당 파일:** `src/tasks/task02CoinGrant.ts`
- **구현 함수:** `createCoinRequest`, `resolveCoinRequest`
- **사전 학습:** `some`, `map`, 상태 전이(pending → approved/rejected), `Number.isInteger`, 불변성
- **AI 활용 힌트:** “pending에서 approved·rejected로만 갈 수 있는 상태 전이 표를 먼저 만들어줘. 코드는 쓰지 마.”
- **테스트 방법:** 정상 신청, 0·소수 신청, 대기 중복 신청, 승인, 수량 줄여 승인, 거절, 이미 처리된 신청 재처리를 확인한다.
- **완료 기준:** pending 신청만 처리되고, 같은 신청이 두 번 지급되지 않으며, 기존 배열을 직접 수정하지 않는다.
- **보안 구분:** 브라우저 시뮬레이션일 뿐이며 실제 승인 권한 확인과 중복 지급 방지는 서버에서 해야 한다.

## 학생 3 — 학생별 코인 잔액과 누적 적립 계산

- **난이도:** ★★☆ 기초
- **개발 목표:** 지급 합계에서 사용한 교환권 비용을 빼 잔액을 구하고, 교환권과 무관한 누적 적립 코인도 계산한다.
- **담당 파일:** `src/tasks/task03CoinSummary.ts`
- **구현 함수:** `calculateCoinBalance`, `calculateTotalEarned`
- **사전 학습:** `filter`, `reduce`, 합계 계산
- **AI 활용 힌트:** “`filter`와 `reduce`를 두 단계로 나누어 생각하는 방법을 예시로 설명해줘.”
- **테스트 방법:** 지급 없음, 지급 여러 건, 교환권 발급, 사용 완료·취소 교환권을 확인한다.
- **완료 기준:** 다른 학생 데이터가 섞이지 않고, 취소 교환권 비용은 차감하지 않으며, 누적 적립은 교환권을 써도 줄지 않는다.

## 학생 4 — 간식 메뉴 조회와 구매 가능 여부

- **난이도:** ★☆☆ 입문
- **개발 목표:** 판매 중인 가상 간식을 찾고 현재 코인으로 교환 가능한지 판단한다.
- **담당 파일:** `src/tasks/task04SnackMenu.ts`
- **구현 함수:** `findEnabledMenu`, `canAffordMenu`
- **사전 학습:** 객체 속성, `find`, 비교 연산자, `undefined`
- **AI 활용 힌트:** “`>`와 `>=` 중 이 과제에 맞는 연산자를 테스트 사례로 설명해줘.”
- **테스트 방법:** 판매 중/중지 메뉴, 정확히 같은 잔액, 1코인 부족을 확인한다.
- **완료 기준:** 비활성 메뉴를 반환하지 않고 잔액이 비용 이상일 때만 참이다.

## 학생 5 — 모바일 교환권 발급 결과 만들기

- **난이도:** ★★★ 도전
- **개발 목표:** 잔액과 메뉴 상태를 확인하고 `issued` 교환권 또는 실패 메시지를 반환한다.
- **담당 파일:** `src/tasks/task05VoucherIssue.ts`
- **구현 함수:** `issueVoucher`

- **AI 활용 힌트:** “성공과 실패를 `{ ok, message, vouchers }`로 표현하는 이유를 설명해줘.”
- **테스트 방법:** 정상 발급, 잔액 부족, 판매 중지 메뉴, 기존 교환권 보존을 확인한다.
- **완료 기준:** 성공 시 한 건만 추가되고 비용·학생·메뉴·상태가 정확하며 실패 시 원본 내용이 유지된다.

## 학생 6 — QR 입력을 가정한 교환권 사용 처리

- **난이도:** ★★★ 도전
- **개발 목표:** 교환권 ID로 `issued`만 `used`로 바꾸고 중복 사용과 취소 상태를 거절한다.
- **담당 파일:** `src/tasks/task06VoucherUse.ts`
- **구현 함수:** `markVoucherUsed`
- **사전 학습:** `map`, 상태 전이, 실패 메시지, 불변성
- **AI 활용 힌트:** “issued→used만 허용하는 상태 전이 표를 먼저 만들어줘. 코드는 쓰지 마.”
- **테스트 방법:** 정상 사용, 같은 ID 재사용, 취소 교환권, 없는 ID를 확인한다.
- **완료 기준:** 허용된 상태만 변경되고 이유를 알 수 있는 메시지를 반환한다.
- **보안 구분:** 브라우저 시뮬레이션일 뿐이며 실제 중복 방지는 서버 DB의 원자적 검증이 필요하다.

## 학생 7 — 누적 적립 코인 랭킹 계산

- **난이도:** ★★★ 도전
- **개발 목표:** 학번별로 지급 내역을 합산해 많은 순으로 정렬하고 TOP 5/10을 만든다.
- **담당 파일:** `src/tasks/task07GameRanking.ts` (파일 이름은 그대로 둔다)
- **구현 함수:** `rankByTotalEarned`
- **사전 학습:** `Map`, `reduce`, `sort`, `slice`, 숫자 비교 함수
- **AI 활용 힌트:** “같은 학번의 여러 지급을 하나로 합치는 방법을 `Map`으로 설명해줘.”
- **테스트 방법:** 한 학생의 여러 지급 합산, 내림차순 정렬, TOP 5 제한, 지급 없음, 원본 순서 보존을 확인한다.
- **완료 기준:** 누적 적립 기준으로 정렬하고 `rank`를 1부터 붙이며 제한 인원만 반환한다. 동점 정책은 문서로 제안하되 임의 확정하지 않는다.
- **개인정보 주의:** 랭킹 화면은 여러 사람이 보게 되므로 실제 학번을 그대로 공개하지 않는다. 가리는 방법(예: `301**`, 별명 사용)을 문서에 제안해 본다.
