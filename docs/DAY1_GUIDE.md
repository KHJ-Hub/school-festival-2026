# 1차 활동(10/30) 따라하기 — 설치 없이 브라우저만으로 시작하기

Surface Go에 아무것도 설치하지 않습니다. **GitHub Codespaces**(브라우저 안에서 열리는 VS Code와 터미널)로 코드를 쓰고, 테스트하고, 올립니다. Node.js와 패키지는 클라우드에서 자동으로 준비됩니다. 막히면 옆 친구에게 먼저 물어보고, 그래도 안 되면 손을 드세요.

## 교사용 진행표 (50분 × 2교시)

| 시간 | 할 일 | 목표 |
|---|---|---|
| 1교시 0~15분 | GitHub 가입, 이메일 인증, 이메일 비공개 설정 | 전원 계정 만들기 |
| 15~25분 | 사용자 이름을 교사에게 제출 → 교사가 저장소 협력자로 초대 → 학생이 메일에서 수락 | 쓰기 권한 받기 |
| 25~50분 | 내 브랜치에서 Codespace 만들기(처음 1~3분 걸림), `npm test`로 빨간 테스트 확인 | 개발 환경 완성 |
| 2교시 0~10분 | 연습 과제(`src/warmup`)로 "BeAT에게 설명 → 코드 붙여 넣기 → 테스트 초록색" 한 번 해 보기 | 전원 첫 성공 |
| 10~35분 | 내 담당 파일에서 같은 방식으로 TODO 구현, 오류 메시지는 BeAT에게 다시 붙여 넣기 | 내 테스트 초록색 |
| 35~45분 | 옆 친구에게 내 함수 설명하기, 설명 못 하는 줄은 BeAT에게 질문 | 이해 확인 |
| 45~50분 | 커밋 → 푸시, 활동 기록 작성, Codespace 중지 | 내 브랜치에 올리기 |

> 진행 팁: 1교시 마지막에 선생님이 빔프로젝터로 연습 과제를 한 번 시연해 주면, 2교시 시작이 훨씬 빠릅니다. 학생에게는 긴 안내서 대신 `docs/ONE_PAGE_CARD.md`를 출력해 나눠 주세요.

### 수업 전에 교사가 꼭 확인할 것

1. **학교 네트워크에서 접속되는지**: 교실 Wi-Fi의 Surface Go에서 `github.com`에 로그인하고 Codespace를 하나 만들어 보세요. 주소가 `*.github.dev`, `*.app.github.dev`인 사이트가 차단되어 있으면 안 됩니다. 차단되어 있다면 정보부서에 해제를 요청하거나, 아래 "대체 방법"을 쓰세요.
2. **학교 구글 계정으로 메일이 오는지 확인**: 학생 계정 한 개로 GitHub 가입을 시도해 인증 메일이 도착하는지 보세요. 학교 구글 관리자가 외부 발신 메일을 막아 두었으면 인증 코드가 오지 않습니다. 이 경우 정보부서에 `noreply@github.com` 허용을 요청해야 합니다. 새 기기(Surface Go)에서 로그인할 때도 확인 코드가 메일로 오니 같이 확인됩니다.
3. **테스트 계정으로 한 번 해 보기**: 새 GitHub 계정으로 가입 → 초대 수락 → Codespace 생성 → `npm test` → 커밋·푸시까지 직접 해 보세요. 이 순서가 가장 막힙니다.
4. **초대 순서**: 학생이 초대를 수락한 **뒤에** Codespace를 만들어야 합니다. 수락 전에 만들면 학생의 개인 복사본(포크)이 생겨 푸시가 엉뚱한 곳으로 갑니다.
5. **사용량 한도**: 무료 개인 계정은 월 120코어시간(2코어 기준 약 60시간)을 씁니다. 8명이 수업 시간만 쓰면 충분하지만, Codespace를 켜 둔 채 퇴실하지 않도록 안내하세요(30분 지나면 자동 중지됩니다).
6. **BeAT 접속 확인**: 학생 계정(또는 학생과 같은 조건의 계정)으로 Surface Go에서 `beat.busanedu.net`에 로그인되고 개인 도우미가 열리는지 확인하세요. 교육청 로그인이나 VPN이 필요한 환경이면 수업 전에 해결해야 합니다. 모델별 하루 사용 한도는 제가 확인하지 못했으니, 학생들이 한 시간 동안 질문을 계속 해도 괜찮은지 직접 써 보세요.
7. **화면이 작습니다**: Surface Go는 화면이 작으니 브라우저 확대를 80%로 줄이고(`Ctrl` + `-`), 왼쪽 탐색기와 아래 터미널만 열어 두세요.

### 대체 방법 (Codespaces가 막혔을 때)

- **github.dev**: 저장소 페이지에서 `.` 키를 누르면 설치 없이 편집기가 열립니다. 다만 터미널이 없어 테스트를 돌릴 수 없고, 코드 읽기·수정·커밋만 가능합니다.
- **StackBlitz**: 공개 저장소일 때 `https://stackblitz.com/github/KHJ-Hub/school-festival-2026/tree/브랜치이름`으로 브라우저에서 실행할 수 있습니다. 푸시는 별도 연결이 필요해서, 막혔을 때의 임시 방법으로만 쓰세요.

## 학생용 1단계 — GitHub 가입

0. 브라우저는 **Chrome**을 씁니다. (Chrome에서 로그인과 Codespace가 확인되었습니다.) 가입 화면이 멈추면 `Ctrl` + `Shift` + `N`으로 **시크릿 창**을 열어 다시 해 보고, 그래도 안 되면 **Edge**로 해 봅니다.
1. <https://github.com> 에서 **Sign up**을 누릅니다.
2. 이메일은 **내 학교 구글 계정 주소**를 씁니다. 비밀번호는 학교 계정 비밀번호와 **다른 새 비밀번호**로 정합니다. (`Continue with Google` 버튼은 쓰지 않고, 이메일로 가입합니다.)
3. 사용자 이름(username)은 **학교 메일 주소·실명·학번·학교 이름이 들어가지 않는 별명**으로 정합니다. 예: `starfox-dev` (GitHub가 메일 아이디 앞부분을 추천해도 그대로 쓰지 않습니다. 사용자 이름은 주소와 커밋 기록에 공개됩니다.)
4. 학교 구글 메일함(Gmail)으로 온 인증 코드를 입력합니다. 메일이 안 보이면 스팸함을 확인합니다.
5. 오른쪽 위 프로필 → **Settings → Emails**에서 아래 두 개를 켭니다.
   - **Keep my email addresses private**
   - **Block command line pushes that expose my email**
6. 내 **사용자 이름**을 교사에게 알려 주고, 초대 메일이 오면 **Accept invitation**을 누릅니다.

> 학교 메일 주소에는 실명이나 학번이 들어 있을 수 있습니다. 위 5번의 이메일 비공개 설정을 꼭 켜서, 커밋 기록과 프로필에 학교 메일 주소가 보이지 않게 합니다.
>
> 비밀번호와 인증 코드는 다른 사람에게 알려 주지 않습니다. 이 프로젝트에는 실제 학번·이름·전화번호를 올리지 않습니다.

## 학생용 3단계 — 내 브랜치로 Codespace 열기

1. 브라우저에서 저장소 `https://github.com/KHJ-Hub/school-festival-2026` 를 엽니다.
2. 왼쪽 위 브랜치 선택 버튼(처음엔 `main`)을 눌러 **2단계 표의 내 브랜치**를 고릅니다. 화면에 내 브랜치 이름이 보이는지 확인합니다.
3. 초록색 **Code** 버튼 → **Codespaces** 탭 → **Create codespace on feature/student-…** 를 누릅니다.
4. **처음에는 몇 분 걸립니다.** "Setting up your codespace" 화면이 오래 떠 있고, VS Code가 열린 뒤에도 왼쪽 파일 목록이 비어 있거나 아래 터미널에 입력 줄이 없을 수 있습니다. **고장이 아니니 기다립니다.** 같은 Codespace를 다시 열 때는 훨씬 빠릅니다.
5. **신뢰 확인**이 나오면 신뢰합니다. 브라우저에 따라 모양이 다릅니다.
   - **Chrome**: "이 폴더의 작성자를 신뢰합니까?" **창**이 뜹니다. **예, 작성자를 신뢰합니다**를 누릅니다.
   - (Edge로 열었다면) 주소줄 아래에 **"제한 모드"(제한된 접근) 안내 줄**이 나옵니다. **관리**를 누르고 **신뢰**로 바꿉니다.
   - 우리 저장소에서만 신뢰합니다. 모르는 사람의 저장소에서는 신뢰하지 않습니다.
6. 왼쪽에 파일(`docs`, `src` 등)이 나타나고, 아래 터미널에 `@사용자이름 ➜ /workspaces/school-festival-2026 ... $` 같은 입력 줄이 나타나면 준비가 끝난 것입니다. 입력 줄이 계속 안 나오면 터미널 패널 오른쪽 위의 **휴지통**으로 닫고, **☰ → 터미널 → 새 터미널**을 엽니다.
7. 터미널 까만 영역을 한 번 클릭하고 입력합니다.

```bash
npm test
```

**빨간 실패가 나오는 것이 정상**입니다. 아직 내가 코드를 안 썼기 때문입니다. 마지막에 `Tests  29 failed | 28 passed`처럼 나옵니다. 이 숫자는 파일이 아니라 **테스트 항목 수**이고, 내 과제를 해결할수록 빨간 숫자가 줄어듭니다. (파일 수 `Test Files`와 항목 수 `Tests`는 다른 줄입니다.)

> 화면 확인: 터미널에 `npm run dev`를 입력하면 오른쪽 아래에 알림이 뜹니다. **Open in Browser**를 누르고 **운영진용** 버튼을 누르면 내 함수의 결과가 보입니다. 끝낼 때는 터미널에서 `Ctrl` + `C`를 누릅니다.

## 학생용 4단계 — AI와 함께 내 과제 만들기

이번 프로젝트에서는 **내가 AI에게 설명하고, AI가 코드를 쓰고, 내가 테스트로 확인하는** 방식으로 개발합니다. 코드를 직접 못 써도 괜찮습니다. 대신 **무엇을 만들지 정확히 설명하는 것**과 **결과가 맞는지 확인하는 것**은 내 몫입니다.

### 먼저 연습: 환영 문장 만들기 (10분)

1. 왼쪽 파일 목록에서 `src/warmup/warmUp.ts`를 엽니다.
2. 터미널에서 `npx vitest run warmUp`을 실행해 **빨간 실패**를 확인합니다.
3. 아래 "AI에게 줄 재료" 방법으로 BeAT에게 코드를 부탁합니다.
4. 받은 코드를 **`welcomeMessage` 함수 안에만** 붙여 넣고 저장합니다.
5. 다시 `npx vitest run warmUp`을 실행해 **초록색**이 되면 연습 성공입니다.
6. 이 연습 파일은 **GitHub에 올리지 않습니다.** (5단계에서 `git add`를 하지 않습니다.)

### 내 과제 진행 순서

1. 왼쪽 파일 목록에서 내 담당 파일(2단계 표)을 엽니다.
2. `TODO` 주석과 `힌트`를 읽습니다.
3. 내 테스트를 실행해 빨간 실패를 확인합니다. 예: 학생 3이면 `npx vitest run task03`
4. **AI에게 줄 재료**(아래)를 BeAT에게 붙여 넣고 코드를 부탁합니다.
5. 받은 코드를 내 담당 파일의 **TODO가 있는 함수 안에만** 붙여 넣고 저장합니다.
6. 내 테스트를 다시 실행합니다. 초록색이면 7번으로, 빨간색이면 **오류 메시지를 복사해 BeAT에게 다시 붙여 넣고** 고쳐 달라고 합니다.
7. **설명해 보기**: 초록색이 되었어도 끝이 아닙니다. 옆 친구에게 "이 함수가 무슨 일을 하는지"를 내 말로 설명합니다. 설명하지 못하는 줄은 BeAT에게 "이 줄이 무슨 뜻이야?"라고 물어 이해합니다.

### AI에게 줄 재료 (이 세 가지를 함께 붙여 넣습니다)

| 번호 | 재료 | 어디에 있나 |
|---|---|---|
| ① | 내 담당 파일 전체 | `src/tasks/taskXX...` (TODO와 힌트가 들어 있습니다) |
| ② | 내 테스트 파일 전체 | `src/tasks/__tests__/taskXX...test.ts` |
| ③ | 타입 파일 전체 | `src/tasks/taskTypes.ts` |

**질문 예시**

> 나는 고1이고 TypeScript 초보야. 아래 ① 내 파일의 TODO 함수를 구현해 줘. ②의 테스트를 모두 통과해야 하고, ③의 타입을 지켜야 해.
> 규칙: 파일의 다른 부분과 타입, 테스트는 바꾸지 말고, 함수 안의 코드만 써 줘. 코드를 준 뒤에는 각 줄이 무슨 뜻인지 쉬운 말로 설명해 줘.
>
> ① (내 파일 붙여 넣기)
> ② (내 테스트 붙여 넣기)
> ③ (타입 파일 붙여 넣기)

### 꼭 지킬 규칙

- **붙여 넣는 곳**: 내 담당 파일의 TODO 함수 안뿐입니다. AI가 테스트 파일, 타입 파일, 다른 학생 파일을 고치라고 해도 **고치지 않습니다.** 테스트를 고쳐서 통과시키는 것은 반칙입니다.
- **import와 함수 이름**: AI가 `import`나 함수 이름을 바꿔서 주면, 원래 파일의 것을 그대로 두고 함수 안의 코드만 가져옵니다.
- **외부 라이브러리 금지**: AI가 `npm install`로 새 라이브러리를 설치하라고 하면 설치하지 말고 "라이브러리 없이 짜 줘"라고 다시 부탁합니다.
- **개인정보 금지**: 실제 학번·이름·전화번호, 비밀번호, 인증 코드는 BeAT에 입력하지 않습니다. 테스트의 가상 학번(`9`로 시작하는 5자리)은 괜찮습니다. BeAT 화면에 "대화 내용은 BeAT 모델 학습에 사용되지 않습니다"라고 적혀 있어도 마찬가지입니다.
- **AI의 답은 틀릴 수 있습니다.** 테스트가 초록색인지로 확인합니다.
- **기록**: 어떤 질문을 했고 AI가 무엇을 줬으며 내가 무엇을 확인·수정했는지 `docs/ACTIVITY_LOG_TEMPLATE.md`의 "AI를 활용한 작업"에 적습니다.

### BeAT 사용 팁

- BeAT는 `beat.busanedu.net`의 **개인 도우미**에서 씁니다. Codespace와 **브라우저 탭을 따로 열어** `Ctrl` + `Tab`으로 오갑니다. (화면이 작아서 나란히 놓기 어렵습니다.)
- **모델**: 기본으로 선택된 모델(GPT-5.1)을 그대로 씁니다. 답이 너무 느리면 아래쪽 모델 선택 버튼에서 `mini`나 `nano`가 붙은 가벼운 모델로 바꿉니다.
- 파일을 붙여 넣기 어려우면 BeAT의 파일 첨부 기능으로 ①~③ 파일을 올려도 됩니다(내 담당 파일, 내 테스트, 타입 파일만).
- 코드를 한꺼번에 못 이해하겠으면 "이 함수를 세 단계로 나눠서 설명해 줘"라고 부탁합니다.

## 학생용 5단계 — 내 브랜치에 올리기

터미널에서 입력합니다.

```bash
git status
git add src/tasks/내파일이름
git commit -m "feat: 학생 N 첫 구현"
git push
```

- Codespaces에서는 GitHub 로그인이 이미 되어 있어서 따로 로그인하지 않아도 됩니다.
- `403` 오류가 나면 초대 수락을 아직 안 한 것입니다. 메일을 확인하고 교사에게 알려 주세요.
- `git status`에 연습 파일(`src/warmup/warmUp.ts`)이 보이는 것은 정상입니다. 올리지 않습니다.
- **다른 파일이 `modified`로 보이면 실수로 고친 것입니다.** 이 설정은 자동 저장이라 글자를 바꾸면 바로 저장됩니다. 그 파일은 `git restore 파일경로`(예: `git restore src/App.tsx`)로 되돌립니다. 어떤 파일인지 모르겠으면 교사에게 물어보세요.
- **다른 학생 브랜치와 `main`에는 올리지 않습니다.**

끝나면 `docs/ACTIVITY_LOG_TEMPLATE.md`를 복사해 오늘 한 일을 적고, 왼쪽 아래 **Codespaces** 메뉴에서 **Stop Current Codespace**로 중지합니다.
